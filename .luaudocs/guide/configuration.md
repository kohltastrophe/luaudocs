# Configuration

Site configuration lives in two optional files: `luaudocs.toml` for settings and `.luaudocs/custom.css` for styling. Without them, `dev` and `build` run on defaults.

## Scaffolding it

```bash
luaudocs init
```

`init` writes `luaudocs.toml` (auto-detecting `[repo] url` from your git remote), user-owned starter pages (`index.md`, `guide/`, `custom.css`), and `.github/workflows/docs.yml` for [GitHub Pages](/guide/deploying#github-pages) when missing.

## Which files are yours

Everything you author lives at the top of `.luaudocs/`:

| Path                                                                       | Owner                                                                               |
| :------------------------------------------------------------------------- | :---------------------------------------------------------------------------------- |
| `guide/`, `public/`, `custom.css`                                          | Yours. Scaffolded once by `init` and never overwritten.                             |
| `index.md`                                                                 | Yours once the `# Generated by luaudocs` marker is removed (see below).             |
| `api/`, `.vitepress/`                                                      | Tool-owned. Cleaned and regenerated on every build.                                 |
| `package.json`, `changelog.md`, `public/llms*.txt`, `public/docmodel.json` | Regenerated in place on every build.                                                |
| `.gitignore`                                                               | Created once when missing.                                                          |

::: warning There is no VitePress config to edit
If `luaudocs.toml` and `custom.css` cannot express what your docs need, open an [issue](https://github.com/kohltastrophe/luaudocs/issues) rather than editing files inside `api/` or `.vitepress/`, which future builds overwrite.
:::

::: details Claiming the landing page without running init
When `index.md` is absent, builds generate one from your `README.md` (or a default hero) marked `# Generated by luaudocs` on line 1, and `init` replaces a still-marked file with its starter hero. Delete that marker line to claim `index.md` so neither `build` nor `init` overwrites your edits.
:::

## `luaudocs.toml`

All keys are optional (commented entries show advanced options):

::: code-group

```toml [luaudocs.toml]
title = "My Library"                  # defaults to the project folder name
description = "One-line tagline"      # site description / meta tag

[source]
entries = ["src"]                     # module roots (dir with init.luau, or a file; [] = guide-only)
# include = ["**/*.luau"]             # only document modules matching these globs
# exclude = ["**/*.spec.luau"]        # drop matching modules from the docs
# projectFile = "my.project.json"     # Rojo project mapping the instance tree (default: default.project.json)
# [source.aliases]                    # require aliases the runtime supplies (no .luaurc): @lute, @std, and @lune are built in
# pkg = "https://pkg.example/docs"    # a docs base URL links `@pkg/x` and its types to <base>/x
# dep = { url = "https://dep.example", model = "https://dep.example/docmodel.json" }  # a luaudocs site: types link to their exact entries
# lune = false                        # true keeps an alias unlinked; false drops a built-in one

[repo]                                # "view source" + edit links + GitHub icon
url = "https://github.com/you/repo"   # (init fills this in from your git remote)
branch = "main"

# [site]                              # branding (paths live in .luaudocs/public/)
# siteTitle = "Short Name"            # navbar text (defaults to title), or false for logo-only
# logo = "/logo.svg"                  # header logo, or { light = "…", dark = "…" }
# favicon = "/favicon.ico"
# ogImage = "/og.png"                 # social-preview image (og:image / twitter:card)
# footer = { message = "MIT", copyright = "© you" }  # shown on pages without a sidebar

# [[site.nav]]                        # header navbar (unset: Guide / API / Changelog as applicable)
# text = "Guide"
# link = "/guide/getting-started"
# activeMatch = "^/guide/"            # routes that mark the entry current (default: its link alone)
# [[site.nav]]                        # nest [[site.nav.items]] under an entry for a dropdown
# text = "API"
# link = "/api/"

# [[site.head]]                       # extra head tags on every page (analytics, verification)
# tag = "script"
# attrs = { defer = "true", src = "https://plausible.io/js/script.js", "data-domain" = "docs.example.com" }
# content = "..."                     # inline body, for tags that carry one

[api]
includePrivate = false                # render _members and @private (badged)
linkRobloxTypes = true                # link Roblox classes/enums/datatypes to creator docs
# reportUndocumented = true           # warn on every public member, class, and type with no doc comment

[docs]
# dir = ".luaudocs"                   # site root (your content + the generated machinery)
url = "https://docs.example.com"      # published URL: sitemap.xml + derived base path
# changelog = false                   # opt out of the CHANGELOG.md -> /changelog page
# includeReadme = true                # keep a README include fresh for your landing page (see below)
# llms = false                        # opt out of llms.txt + llms-full.txt
# model = true                        # publish public/docmodel.json, so other sites can link into this one
```

:::

Unknown keys fail validation so typos cannot silently disable settings.

Key details:

- **Base path.** A path in `[docs] url` (`user.github.io/repo/`) becomes the site's `base`; see [Deploying](/guide/deploying#base-path-vs-custom-domain).
- **Runtime aliases.** Requires through an alias not in `.luaurc` (`require("@lute/fs")`) are treated as external runtime modules rather than [`require-unresolved`](/guide/reference/diagnostics#warnings). Re-exporting one renders a property showing the `require` expression, and types accessed through it (`fs.File`) link to `<base>/<module>`. Lute (`@lute`, `@std`) and Lune (`@lune`) are built in; `[source.aliases]` registers custom aliases or overrides built-in ones (`.luaurc` aliases always take precedence).
- **Linking into another LuauDocs site.** When a dependency publishes its doc model (`[docs] model = true` writes `public/docmodel.json`, such as [luaudocs.pages.dev/docmodel.json](https://luaudocs.pages.dev/docmodel.json)), configure `[source.aliases]` with `{ url, model }`: types reached through that alias link directly to their `#anchor` on the remote site. `model` accepts a URL (cached per user with offline fallback) or a local path; unreadable models [emit a warning](/guide/reference/diagnostics#renderer-warnings) and fall back to module-level links.
- **AI tooling.** `build` writes `public/llms.txt` and `public/llms-full.txt` for deployed sites. `llms = false` disables those two files without affecting the repository-root `llms.txt` generated by [`luaudocs llms`](/guide/coding-agents).
- **The API sidebar.** Derived automatically from public access paths with no configuration; see [How It Works](/guide/how-it-works#the-api-sidebar).
- **Documentation coverage.** `[api] reportUndocumented = true` emits an [`undocumented`](/guide/reference/diagnostics#warnings) warning for each public member, class, or exported type lacking a doc comment (`Widget:refresh`), failing `luaudocs build --strict` in CI. Private items and re-exports are excluded.

::: details Putting your README on a landing page you author
Without a custom `index.md`, builds already render `README.md` as your landing page. Set `includeReadme = true` when you maintain a custom `index.md` and want to embed `.vitepress/generated/readme.md` (with `moonwave-hide-before/after-this-line` stripped) via a VitePress `@include: ./.vitepress/generated/readme.md` comment. Relative links in the README are rewritten to doc pages or `[repo]` GitHub URLs.
:::

## The navbar

When `[[site.nav]]` is unset, LuauDocs generates **Guide**, **API**, and **Changelog** links automatically (with `activeMatch` on Guide and API so they stay highlighted across subpages). Defining `[[site.nav]]` replaces the default navbar wholesale.

## The guides sidebar

The `/guide/` sidebar is built from page frontmatter and subdirectories:

```yaml
---
title: Getting Started # or sidebar_label; falls back to the first heading
sidebar_position: 1 # or order
description: One-line summary # optional; else the first sentence of the page
---
```

`sidebar_position` orders pages relative to siblings in the same folder; unpositioned pages sort after positioned ones alphabetically by title, and `index.md` always leads its folder. `description` is used as the page summary in `llms.txt`.

Folders and files starting with an underscore (`_drafts/`, `_partial.md`) are excluded from the sidebar, build output, search, and `llms.txt`.

When `guide/` contains loose pages, everything sits under a top-level **Guide** heading; when `guide/` contains only subfolders, each folder becomes its own top-level sidebar section.

### Group settings

Configure a guide folder with a `_category_.json` (or `.yml` / `.yaml`) sidecar:

```json
{
	"label": "API Reference",
	"position": 3,
	"collapsed": true
}
```

- **`label`**: group title (defaults to the title-cased folder name).
- **`position`**: order among sibling pages and folders (decimals such as `2.5` are supported).
- **`collapsed`**: starts the group collapsed (default `false`).
- **`collapsible`**: set to `false` to render a static header without a toggle.

A folder with an `index.md` can set `sidebar_position`, `collapsed`, and `collapsible` in `index.md` frontmatter instead (`_category_` wins per key when both exist; `title` in `index.md` names the page rather than the group). Invalid `_category_` files fail the build.

## Styling

`init` scaffolds `.luaudocs/custom.css`, which loads after the default stylesheet on every page so you can override brand colors, hero gradients, or [VitePress theme variables](https://vitepress.dev/guide/extending-default-theme). Delete the file to stop loading it.

### The code font

Code blocks and inline code use bundled [Fira Code](https://github.com/tonsky/FiraCode) with ligatures enabled (`->`, `..`, `<=`; Luau's `~=` stays unligated). Customize it in `custom.css`:

```css
/* keep the font, drop the ligatures */
.vp-doc code {
	font-variant-ligatures: none;
}

/* or use something else entirely */
:root {
	--vp-font-family-mono: "JetBrains Mono", monospace;
}
```

## Guide-only sites

Set `[source] entries = []` to skip the extractor and build only your landing page, guides, and changelog. (This site points `entries` at [`examples/Flux`](/api/) so the guides can embed live API output.)
