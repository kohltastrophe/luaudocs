# Coding Agents

While your deployed site serves `/llms.txt` to web tools, coding agents working in a local checkout need an index that links directly to repository files and line numbers:

```bash
luaudocs llms
```

This writes `llms.txt` at your project root, indexing your guides and every public module, type, and member linked to its declaration lines. Because it only runs extraction and markdown rendering, it requires no `luaudocs init`, VitePress build, or docs directory.

## What it contains

Here is the `llms.txt` generated for this repository (indexing the guides and [`examples/Flux`](/api/)):

::: code-group

<<< ../../llms.txt{md}

:::

- **Guides** link to their local Markdown files with their frontmatter summaries.
- **Each module gets a section** ordered like the API reference and headed by its [access path](/guide/how-it-works#access-paths-not-folders) (`Flux.Util.Queue`), listing the module, its types, and its members.
- **Every entry is a Luau signature** linked to its `file:line` span, right below its doc comment.
- **Bracketed labels** carry badges (`[Yields]`, `[Server]`, `[Read Only]`, `[from State]`, and deprecation notes).
- **`CHANGELOG.md`** appears under `Optional`.

Because `llms.txt` is derived solely from committed repository files, every checkout produces identical bytes. Commit it alongside your source code.

## Pointing agents at it

Reference `llms.txt` in your root `AGENTS.md` or `CLAUDE.md`:

::: code-group

```md [AGENTS.md]
## Public API

`llms.txt` indexes this library's guides and public API. Read it before using or changing the API. After changing the public surface, a doc comment, or a guide, run `npx luaudocs@0.3.0 llms` and commit the regenerated `llms.txt` with your change.
```

```md [CLAUDE.md]
## Public API

@llms.txt

After changing the public surface, a doc comment, or a guide, run `npx luaudocs@0.3.0 llms` and commit the regenerated `llms.txt` with your change.
```

:::

Claude Code expands `@llms.txt` into context automatically (ideal for small libraries; for larger ones, reference `llms.txt` by name so agents read it on demand).

The generated `llms.txt` header includes the exact `npx luaudocs@0.3.0 llms` regeneration command, and running `luaudocs llms` leaves the file untouched on disk when nothing changed. When upgrading LuauDocs, regenerate `llms.txt` and update the version pin in your agent instructions.

## Checking it in CI

Use `--check` in CI to fail when the committed `llms.txt` is missing, stale, or encounters extraction errors:

```bash
npx luaudocs@0.3.0 llms --check
```

A normal `luaudocs llms` run also aborts without overwriting `llms.txt` if extraction errors occur, so a temporary syntax error never strips modules from the index.

## Where it lives

Pass `--out <file>` to write the index to another path (all relative links and the embedded regeneration command adjust automatically).

`luaudocs llms` only overwrites an existing file if line 1 starts with `<!-- Generated by luaudocs`; removing that marker claims the file as hand-maintained. Setting `[docs] llms = false` only disables the site's `public/llms*.txt` files and does not affect `luaudocs llms`.
